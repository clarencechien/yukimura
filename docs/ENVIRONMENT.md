# 髒雪、建物與障礙物材質

> 歷史／研究文件（2026-10-14 整理）：以下「目前」、測試數據與待辦指原記錄階段，不代表 v22 現況；舊版命令如需精確重現，應使用對應 Git 版本。目前採用範圍以 [狀態與交接](STATUS.md) 為準；參閱 [完整索引](INDEX.md)。

人物與戰場共用冬季天空反射、冷色環境光與暖色主光。主要場景使用 Babylon.js PBR；v10 在既有投影、風雪與煙霧之上，補上地表的近距離細節和接地層次。

- **地面**：整段戰場共用 2048² 基礎色、1024² 法線及表面參數；以多尺度噪聲打散雪泥交界，降低腳印的整齊點列感。另加一張 512²、308,528 bytes 的原生 PBR detail map，以四公尺為尺度補上碎雪、泥粒與凹凸；同一貼圖供雪堆使用，不把整張戰場升成 8K。
- **融水與接地**：42 處狹長車轍積水、126 片碎冰、140 塊半埋碎石和 85 叢枯草。泥污薄片圍繞火盆、營門、木障礙及碎木；雪堆用多圈曲面、灰褐邊緣與不規則輪廓。積水使用低粗糙度與既有天空反射，沒有即時反射場景、流體或碰撞模擬。
- **木障礙與門柱**：共用木纖維、裂隙、下緣受潮及局部煙燻；不為每根木頭下載一套材質。
- **石牆與灰泥**：石縫凹凸、牆腳受潮、垂直污漬與細裂紋；城樓增加石造基座、下緣木梁及角柱。
- **屋瓦與積雪**：瓦脊、接縫及不均勻殘雪；地面防線旁加入不規則、邊緣貼地的薄雪堆。
- **光影**：減少近景霧白、調整冷暖光比例，保留遠景霧層；角色腳底改為共享柔邊接觸陰影。四盞共用火光依玩家距離分配到左右最近的火盆，避免右側火焰缺少對應光源；每個 PBR 材質最多同時計算四盞燈。
- **火盆與兵陣**：球狀火焰換成共用貼圖的八片直立火床及 Babylon.js 原生粒子火舌／火星；火床固定在盆口，飛升的粒子不會讓整盆火忽然熄滅。桌面／觸控／減少動態模式的粒子容量分別為 192／128／60，暫停時凍結。遠景兵陣增加斗笠、頭部與雙腿輪廓；仍為合併靜態佈景，不參與近景戰鬥。

靜態物件繼續依共用材質合併；合併前補齊頂點顏色，合併後保留頂點透明度，使污漬與積水邊緣不變成硬圓片。實際近景檢查修正了薄片朝向和這項透明度問題，並加入原生合併網格的回歸檢查。新增四種共用地表材質，沒有逐物件貼圖或全螢幕 SSAO／即時反射成本。

地面污跡是預先製作的美術，不是即時足跡、流體或動態積雪模擬。法線細節不改變碰撞或角色站立高度。材質已改善，但建物本體仍是簡化幾何，不應把它稱為完成高模場景。

`tools/build_environment.py` 以 Blender 內附 NumPy 離線產生共用 PNG，不在每幀繪製 Canvas。重建用 `npm run environment`，精確大小及雜湊記錄在 `public/environment/manifest.json`。這些資產需跟遊戲一起部署，不依赖外部圖片服務。

v10 共 19 張環境貼圖、8,766,781 bytes，比 v8／v9 增加 555,171 bytes。`node tools/capture-environment.mjs` 保存 `winter-ground.png`、`winter-gate.png`、`winter-camp.png`：這三張為實際遊戲場景的開發檢視鏡頭，隱藏 HUD／近景軍隊以檢查材質；一般玩家鏡頭的實戰另見 `battle.png` 與 `mobile.png`。

目前已驗證 Chromium 軟體 WebGL 與手機尺寸／觸控流程；材質和靜態投影增加了紋理記憶體及繪圖成本，尚無實體手機幀率資料。

## v11：低成本材質光照與電影調色

- Babylon.js 材質端啟用 ACES tone mapping，曝光 1.35；後製只做顯示色域的冷暖調色、微量局部對比及暗角，避免二次 tone mapping。原本五次取樣的墨色處理改為保留陰影細節、較淡的輪廓和受限銳化；移除紙色高光覆蓋與顆粒，保留真田赤紅。
- 共用天空反射由每面 32² 改成 64²，加入天空／地面差異、暖色開口與冷色側光。啟動時建立一次；仍是近似天空，不是 HDRI 實景、動態反射或即時全域光照。
- 重用角色既有 ORM 的紅色 AO 通道，讓接縫與甲片遮蔽影響環境光。人物及群兵接收既有 shadow map；沒有新增光源或陰影貼圖。
- 幸村與家康啟用帶遮罩的原生 clear coat。`npm run look` 從現有烘焙表面資料辨識低金屬度、較低粗糙度的漆甲；布料、木頭、皮膚與裸金屬不套漆層。兩張遮罩分別 512²／256²，共 **99,739 bytes**，不必重烘焙高模。兩種小兵不啟用 clear coat，仍共用材質與 GPU 動畫。
- 觸控裝置保留 **一層後製、五次場景取樣**。桌面增加原生亮部抽取和兩次分離模糊，三個中間結果都只有四分之一寬高（各為完整畫面的 1/16 像素）；既有調色步驟一併合成光暈。使用 8-bit 色彩目標，沒有額外的全尺寸合成步驟、SSAO、景深、SSR 或光追。

PostProcess 的尺寸參數控制「輸入目標」，不是最後輸出大小。桌面的第一個場景輸入保持完整尺寸，最終調色同時讀取該原圖及小尺寸模糊圖，避免把整個遊戲降成四分之一解析度。實際檢查在 `docs/screenshots/lighting-budget.json`：1066×666 原始場景，三個 266×166 中間目標。這是渲染配置證據，**不是增加 18.75% GPU 時間或真機 FPS 的測量**。

`tools/capture-look.mjs` 保存同一鏡頭／人物姿勢的 `lighting-after.png`、`material-after.png`；`*-before.png` 是 `0ff0bef` 原版的實際引擎截圖。環境風雪和火舌相位會不同，沒有替換模型、合成插畫或宣稱已達完整 3A 資產品質。完整重建 `npm run models` 會同步更新漆甲遮罩；單獨更換烘焙貼圖後也須執行 `npm run look`，測試會檢查來源雜湊。

## v12：黑金家康的 Boss 輪廓

家康的遊戲模型倍率由 1.13 提至 1.65（小兵為 1，幸村為 1.15），再以 Blender 修改家康專用的部件副本：肩甲向外展開、金色羊齒兜飾加寬加高、披風加寬。肩甲冠部及首尾甲片、兜帽前緣改為金色大面；其餘維持冷黑漆甲、暗色布料和披風。這是修羅世界的誇張武將造型，不是家康真實體型或甲冑的考據復原。

`tools/refine_ieyasu.py` 的 `commander_silhouette` 只修改家康組裝副本，不改幸村和小兵的共用原件。`npm run models` 重建可編輯 Blender 來源、遊戲 GLB、烘焙貼圖、GPU 動畫 palette 與漆甲遮罩。v12 當時沿用 18 骨架、六組動畫、單一材質與既有照明，沒有新增即時光源或渲染步驟；v22 家康已改為 92 骨架、5 個材質，1.65 倍首領尺寸仍保留。放大的是角色 body instance；邏輯根節點保持原尺寸，4.8 公尺攻擊半徑與預警圈不會跟著放大。

`node tools/capture-boss.mjs` 保存 `boss-battle-after.png` 和 `boss-close-after.png`。比較圖使用同一個本陣前方位置、鏡頭、idle 姿勢及兩名小兵；`before` 為 v11 原模型與 1.13 倍率。這些是開發檢視鏡頭的實際遊戲輸出，環境粒子相位可以不同。
