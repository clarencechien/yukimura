## 這輪能玩什麼

**六文不渡，赤槍開路。**

燼關前，守關的鬼武者仍握著生前的刀。他已忘記效忠誰，卻沒有忘記攔住每一個離去的人。幸村壓低身勢，收槍，踏穩——赤槍落處，讓這場戰爭先放過一個亡魂。

- 按 **J／空白鍵**，或手機的 **出槍** 按鈕：蓄勢、短刺、收槍。收槍前不能重複出手，沒有自動連擊或按住連發。
- **對手**：預設燼關鬼武者；亦可切回上一輪怨火封印，使用相同判定規則。
- **槍尖可及**：槍尖進入目標上身的碰撞圓才扣血；三次命中擊倒鬼武者／破封。
- **一步之外**：目標位於射程外，出槍會刺空。改變間合會重置目標；攻擊途中不能切換。
- **再戰鬼武者／重聚封印**：重置血量、命中次數與攻擊動作；暫停、逐次試槍。
- **命中特效**：切換火星、短槍光軌、封印震動與小幅鏡頭震動；開關不改變傷害規則。70 ms 命中停頓屬於動作時序，保留。
- **音效**預設關閉，可自行開啟；為 Web Audio 合成的簡短出槍／命中聲，不是專業錄製的兵器音效。
- **顯示槍尖判定**：青圈是目標碰撞範圍，白點為槍尖，金點表示有效攻擊幀。此項用於動作檢查。

手機支援觸控；全螢幕依瀏覽器支援，亦可轉橫向。切到背景分頁會暫停，回來後手動繼續。偏好減少動態時，不啟用漂浮落燼與鏡頭震動。

## 鬼武者的反應

![戒備到伏地的八個姿勢](combat/enemy-poses.jpg)

敵人採黑漆甲、藍黑繫繩、鐵面頬與冷色眼神，與幸村赤甲區分。原有四姿勢與頭部朝向修正之外，這輪以原圖作參考，再用 image gen 補繪輕受擊、屈膝、手掌承重、側身落地四姿勢。按人工檢視的邊界裁切、對齊接地基準，保留各姿勢的原始身體形狀。檢視圖中以頭部高度下降順序排列跪下與撐地，避免過渡時反而抬頭。

- 非致命命中：輕受擊並與主角共同停頓 70 ms；停頓後輕受擊至 90 ms → 後仰至 220 ms → 輕受擊回正至 360 ms → 戒備。
- 最後一擊：停頓後，輕受擊至 90 ms → 後仰至 180 ms → 屈膝至 300 ms → 跪下至 420 ms → 手掌承重至 540 ms → 側身落地至 680 ms → 伏地至 1000 ms → 700 ms 漸淡，最後離場。以上為停頓結束後累計時間。
- 暫停也凍結敵人的反應時間；重置會立即恢復戒備與三點生命，沒有殘留的死亡回呼。
- 倒地圖已畫出膝彎、手臂承重與軀幹屈曲，程式不把站姿旋轉成橫躺木偶，也不做非等比壓縮。

**這是八張關鍵姿勢切換，不是完整骨架動畫或 30 張不同敵人動作／秒。** 各圖的甲片、刀長與身體投影仍有生成差異，腳掌也尚未使用跨姿勢的 IK 約束。新增屈膝讓重心降低有中途姿勢，但後仰轉向前傾、撐地轉側躺仍有跳幅，不能當作已完成流暢的物理動畫。下一輪應對這兩段補繪更一致的關節路徑，再增加敵人的進攻動作。

## 從動作到命中

沿用上一輪的 **15 個固定肢段與骨盆／雙膝連動**。主角仍使用原有 Blender 動作；敵人使用本輪整合的八個姿勢。

1. 角色畫面仍為 30 fps 的持槍待機／短刺貼圖；Phaser 負責場景、貼圖渲染、輸入、粒子與 tween。
2. 在原插畫手動標記槍尖 `(1520, 350)`，套用與 Blender 動畫相同的槍位移，再換算為場景座標。碰撞資料來自 [spear-track.json](combat/spear-track.json)。
3. 僅在第 **15–16 幀**有效（零起算 14–15）。使用前後槍尖位置的線段對圓判定，避免低更新頻率越過碰撞位置。每次攻擊最多傷害一次。
4. 命中時角色動畫停頓 70 ms，同時觸發火星與封印震動；收槍完成才重新接受攻擊。
5. 前腳與後腳腳尖沿用固定接觸點，在對應位置加接地陰影；背景是新生成的一張空場景畫，沒有預先畫死的人物。

![槍尖與封印碰撞範圍檢查](combat/hit-check.jpg)

這是固定站位、單目標的戰鬥回饋試作。鬼武者會受擊與倒下，目前不主動攻擊；封印仍可選作測試目標。**沒有敵人 AI、移動尋路、方向切換、連招或完整關卡**。背景石台不是可碰撞地形；陰影、人物高光與材質不是即時 3D 光照。圖層膝踝接縫與肩胯轉動仍有改善空間。

## 引擎與成本

使用 **Phaser 3.90.0／MIT**，從 npm 官方套件取得，將固定版本與授權一併放在 [vendor](combat/vendor/)。已核對 npm 套件 SHA512，並保存 [來源與檔案 SHA256](combat/vendor/PROVENANCE.json)。執行時不依賴外部 CDN，不修改主遊戲的 Babylon.js 或根目錄依賴。

| 載入方式 | 角色每幀 | 角色圖集 RGBA8 記憶體 |
| --- | --- | --- |
| 小於 900 px 的視窗 | 512×320 | 待機＋短刺，共約 45 MiB |
| 桌機視窗 ≥ 900 px | 1024×640，兩頁／動作 | 待機＋短刺，共約 180 MiB |

敵人另加一張八姿勢圖集：手機 1536×2048，約 **12 MiB**；桌機 2304×3072，約 **27 MiB**。合計角色貼圖約 57／207 MiB，尚不含背景、渲染緩衝與可能的 mipmap。此頁只載入暖火光一種角色補光。壓縮檔案大小不等於顯示記憶體；正式手機遊戲還需要 KTX2／更小圖集、按需換動作，以及實機效能量測。圖集規格在進入頁面時選擇，旋轉或調整視窗不會中途重新載入另一套。

新背景母圖為 1536×1024，參考既有地獄概念圖，以 image gen 生成一次無人物石台，再輸出 WebP。來源見 [原圖](../../../assets/source/jigoku-2d/combat-arena.png) 與 [素材紀錄](combat/art-provenance.json)。幸村重用既有 Blender CPU 輸出；鬼武者是新生成的 2D 姿勢圖，未經 Blender 建模或重新打光。沒有使用 Modal／GPU 建模。

## 驗證與重建

- [10 項戰鬥規則檢查](../../../tools/check_jigoku_combat_state.mjs)：三擊破封、防重複傷害、有效幀與停頓、遠距離刺空、不同更新間隔、暫停與重置、線段碰撞邊界、敵人反應順序、反應暫停與重置、目標切換、非致命受擊回正且不進入倒地姿勢。
- [瀏覽器檢查結果](combat/browser-check.json)：實際 Phaser 載入、桌機 HD 與手機圖集、鍵盤／觸控、命中／刺空／破封、暫停、特效關閉、鬼武者受擊姿勢、完整死亡順序、閃光到期清除與錯誤請求檢查。
- [影片檢查](combat/video-check.json)：78 張實際瀏覽器畫面、固定 30 fps、2.6 秒；影片從敵人剩一點生命開始，呈現最後一擊與倒地。錄影在 Phaser 啟動前安裝可控時鐘，再取樣畫面，避免更換時鐘打亂 TweenManager 的時間基準；不代表實體手機可以穩定 30／60 fps。GIF 以 30／30／40 ms 近似，均勻幀間隔請看 MP4。

從 repo 根目錄啟動 Python 靜態伺服器後，開啟 `/docs/routes/jigoku-2d/combat/` 路徑。此頁不用額外安裝 npm 依賴；檢查腳本沿用 repo 的 Playwright／Chromium。

```sh
python3 -m http.server 8080
# 另開終端執行檢查與重建：
python3 tools/prepare_jigoku_combat.py
python3 tools/prepare_ghost_warrior.py
node --test tools/check_jigoku_combat_state.mjs
node tools/check_jigoku_combat.mjs
python3 tools/package_jigoku_combat_preview.py
```

圖像重新打包需 Pillow／NumPy；瀏覽器錄影打包需 FFmpeg。瀏覽器檢查會自行啟動並關閉臨時 HTTP 伺服器。
