- `npm test`：4 項通過，0 失敗。

  - 正式建置桌面：模型、十人隊伍、敘事面板、移動、陣形、暫停／繼續；無 JS 例外或 HTTP 錯誤。

- 正式建置不提供開發測試步進介面。

## 限制與未完成
- Chromium 使用 SwiftShader 軟體繪圖，已自動降低內部解析度；這不是實體手機 FPS 認證。
- 個別十勇士外觀與忍術、專用家康模型、骨架動作、音效尚未實作。
- 史料：大阪城官方站、Wikipedia 嘗試讀取均 CONNECT 403，未假裝已讀或驗證使用者提供的引文。
- Modal：最初缺少變數；後續小寫變數已注入，重新呼叫仍因無法連上伺服器失敗。`api.modal.com` 的 HTTP 檢查為代理 CONNECT 403，不是已證明 token 無效。需套用網路允許清單後再試；可能還需支援 SDK 的 HTTP/2 連線，必須以實際執行結果判定。
- 模型生成目前確認為本機 Blender；Modal 工作程式已備妥但遠端執行未通過。
- 設定草稿保存與實際發布是不同步驟；未宣稱已部署公開網站。

- `npm run models`：Blender 4.3.2 CPU 成功匯出四個 GLB、三張共用貼圖與可編輯源檔。幸村 9,886 三角形、14 骨、idle/run/slash 三組動作；約 3.32 MiB 的幾何／動畫／貼圖總下載量。
- `npm run models:preview`：Cycles CPU 組裝預覽成功。另以 Babylon.js 載入實際 GLB，保存正面／背面／揮槍近景，與 2D 美術目標分开。
- `npm test`：10/10 通過。檢查戰鬥規則、面數／大小預算、共用貼圖雜湊及 PNG 尺寸、buffer views 範圍、唯一 UV、非白色陣營頂點色、骨架權重及三組非靜態動作。
- `npm run test:e2e`：3/3 通過。production 桌面＋手機直橫向、觸控移動和戰技；dev 完整通關、二周目、敗北重試。新增驗證 idle/run/slash 的實際切換；無頁面例外或資產 HTTP 錯誤。
- 視覺檢查發現並修正 Blender 的假白色 COLOR_0（真實配色在 COLOR_1）與合併零件時 UV 名稱不一致；強制匯出 active Color、統一 PaintedAtlas，並加入防退化檢查。

限制：Chromium 使用 SwiftShader，手機測試是尺寸／觸控模擬，不能據此宣稱真機流暢。目前敵兵／隊友沒有骨架、資產沒有 LOD。高精度雕刻、重拓樸和高模法線烘焙尚未完成；程序幾何與貼圖的美術品質仍明顯落後 2D 插畫。Modal 在本輪沒有執行；遠端 helper/資產回收腳本僅同步更新並做 Python 語法檢查。
